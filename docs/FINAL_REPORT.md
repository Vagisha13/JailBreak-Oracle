platform. Every capability claimed by the implementation tracker is implemented,

campaign orchestrator → agents → mock/external targets → persisted findings →
reports → frontend) with zero external services, or point the LiteLLM-backed
providers at real models and watch the same pipeline exercise them live.

## Real-provider validation (gpt-4o-mini, consent-gated, authorized-lab framing)

- Connectivity probe: passed.
- 6-round campaign: **COMPLETED**, 28 real LLM calls, 28,991 tokens,
  **$0.008** cost (cap $1). Every attack was generated by an LLM, executed
  against the target, and evaluated by real judging models.
- Outcome: 0 findings. This is the **expected, honest** result against a
  production-aligned model that refuses the payloads. The pipeline,
  persistence, budgets, and verification flow worked end-to-end.
- Surfaced + fixed during validation: the attacker's generation prompt needed
  explicit authorized-red-team context or aligned models refuse to emit JSON.
  Applied once in `AttackerAgent` (root + mutation prompts); mock behavior
  unchanged.
- Credentials handled safely: the validator prints key presence only, reads
  `.env.local`, and `.env.example` ships placeholders.

## Security posture

- AuthZ: JWT + RBAC (admin/researcher), ownership checks on all data routes,
  self-registration disable switch (`ALLOW_REGISTRATION`).
- Rate limiting: per-IP buckets with trusted-proxy enforcement (XFF ignored
  unless the peer is a configured proxy).
- Observability: structured JSON logs with pass-based secret redaction and a
  strict context-field whitelist; router logging now uses the redaction-safe
  logger (fix applied).
- Frontend: `X-Powered-By` disabled; OWASP response headers; 401 auto-logout;
  deterministic Vitest coverage of the API client.
- Governance: per-campaign USD budgets with pre-call tripwires + persisted
  ledger; campaign leases, heartbeats, and stale recovery for multi-worker
  safety.

## Known honest limitations (documented, non-blocking)

1. **Aligned models often refuse**: against models like gpt-4o-mini, real
   campaigns generate/execute/evaluate correctly but the target refuses —
   0 findings. The mock target (deterministic catalog) is the reliable demo
   path and the CI default.
2. **Docker builds not smoke-tested here**: no Docker daemon on this machine;
   `docker compose config` validated only.
3. **SQLite dev uses keyword memory fallback** (no pgvector); Postgres/pgvector
   is the production path.
